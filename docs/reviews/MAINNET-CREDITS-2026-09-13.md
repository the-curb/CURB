# Mainnet preparation — credit read states and payment hints

Local changes for remaining-work items R02 and R03, 13 September 2026. These changes do not constitute independent review, a public deployment or approval to receive payments.

- `receipts()` reports `receiptsState` independently of `pendingState` / `pendingFault`. An unread or absent index has `waitingForRate: null`, not zero, while successfully read credited receipts remain visible.
- `keyAccount()` reports `balanceState` independently of pending payments. `pendingState` is `READ`, `UNREAD`, `NOT_INDEXED` or `NOT_REQUESTED`; `pending` is an array only for `READ`, and otherwise null. A successfully read empty queue is `READ` with `[]`. Malformed index data is `UNREAD`.
- `pending: false` does not read the index and is not an outage. Existing funded admission and debit continue to work when the pending index or top-up evidence is unavailable. Balance row failures still block spending.
- `/api/credits`, `POST /api/keys`, unpaid endpoint responses and Services use `topUpReadiness()`, which delegates to the existing current-chain/configuration/immutable checks and the 30-minute code/rate limit. A stale MATCHES observation by itself cannot invite payment.
- The API names a top-up destination only when both reads qualify. Every invitation includes a `validUntil` derived from the oldest required observation, rather than extending freshness from request time. Stateless key creation still returns a key when the evidence is held.
- The credit UI composes amount and destination from the same quote response, displays its network/token and unit scale, expires the bytes, and clears an old quote after input changes or a failed replacement request. A readable balance remains visible with a separate notice when pending payments are unknown.

Client compatibility: consumers must handle `pending: null`, nullable `waitingForRate`, the new state/fault fields and `topUp: null`. Do not convert these nulls to zero or empty arrays. The key balance endpoint spreads the new account fields and retains HTTP 200 when the balance was read but the pending index was not; balance read failures retain HTTP 503.
