# Launch checklist — the credit desk on Robinhood Chain

**Status:** a checklist, not a decision. Prepared 13 September 2026. It executes [the token record](TOKEN.md) (decided by the product owner, 12 September 2026, Robinhood Chain included). It follows [the deployment plan](DEPLOYMENT.md) and [the operator policy](OPERATIONS.md), both still proposed. The treasury creation and signer record are complete. It establishes no approved public CompanySeries deployment, no configured CURB/CreditDesk deployment and no independent review.

**Nodes.**

- The tools live in `contracts/scripts/` and run from `contracts/`.
- They read Robinhood Chain (chain id 4663, the `robinhood-mainnet` profile) through `CURB_RPC_URL` if set in the shell. Otherwise they read the public node `https://rpc.mainnet.chain.robinhood.com`.
- The deployment tool prints the node's host on its first line. A keyed URL is never printed or written into a record.
- The tools read state only, except row 12's `priceSource.fromBlock` check, which reads the pool's logs before that block. On the public node that is one query (any width under 10,000 matches). On a width-capped endpoint it reads at most sixty-four pages and says how far it read.

**Measured 13 September 2026:**

- dRPC with a key (`lb.drpc.live`): full archive state; `eth_getLogs` up to 100,000 blocks, with no cap on results. The site reads everything through it first (`CURB_RPC_URL` and `CURB_RPC_ROUTE=all` on Railway, set 21 September 2026), with the public node as the fallback. Unset, `CURB_RPC_ROUTE` sends head reads to the public node first to spare the balance.
- dRPC without a key: about 200 blocks a query. Alchemy's unpaid tier: ten. Enough for the tools, not the tick.
- The site's readers halve a query refused for width, for matching too much, or for taking too long.

## Who

- **The product owner** decides the signers, the launch and the pool. Decisions are recorded by name and date; the site never upgrades one itself.
- **The signers:** three people with their own Robinhood Chain wallets. They own the operator's Safe, 2-of-3 as the policy proposes: the treasury every top-up goes to.
- **The reviewer:** a named person, not the record's author. They check the tool's output against the chain and sign with name and date. Without that name the deployment tool refuses.
- **The operator** holds the tools' shell, the deployer key and the Railway app service's variables. The key is ETH-funded on Robinhood Chain for gas, and never in this repository or a chat.

One person may hold several roles; the records say which.

The line beneath is derived from the record by `lib/launch/status.ts`: the Safe's evidence file, the `CURB_CREDITS` line, the last code and rate reads, credited top-ups. It states what is on chain (the treasury) and what is not (the token, the desk, the position series). It advances as rows are done:

- a valid treasury creation record;
- a configured desk;
- matching code for the configured token and treasury;
- a rate read;
- a credited top-up tied to the current chain and desk index.

Code and rate reads older than thirty minutes do not advance it: a display rule, not an uptime promise. Missing evidence means unconfirmed, not proof that nothing exists on chain. The footer (`BRAND.stage`) and the series' stage line say the same. None of it makes the eight refused claims or says anything is sold.

## The rows

**Order.** Before row 3, finish what TOKEN and the [mainnet dossier](../mainnet/PREPARATION.md) require: the independent-review scope and its actual funding, launchpad/terms/authority review, and the approved proceeds formula. Rows 1–2 are completed treasury actions; do not create another Safe to repeat them. Run rows 3–10 after their decisions, then **12 → 13 → 11 → 14 → 15**. A supported, configured, freshly read pool precedes the first public-chain payment test. Unpriced-payment recovery belongs in an isolated rehearsal. ## What is refused by design, and stays refused

- A record nobody reviewed by name; a public chain without `--reviewed`; a key from anywhere but the operator's shell; a second deployment over an existing evidence file, which only a person moves aside (rows 5–7).
- An address copied from a documentation example. Every address comes from the chain via a tool, or the explorer via the named reviewer.
- Any edit to `contracts/src/CreditDesk.sol` or the compiler settings after deployment. CI refuses it until the build record is re-recorded (`check:build`: the record is not this source's bytecode). Re-recording turns a correct desk into a MISMATCH on `/services` and `/api/state`. A change is a new desk, record and deployment.
- A typed-in price ([the conversion](TOKEN.md#the-conversion-stated)). Until row 13 nothing is quoted; a top-up meanwhile is indexed and waits.
- A promise the code does not keep: the eight claims refused for the position are refused for the token ([the token record](TOKEN.md#what-the-token-does-not-do)). The services page says what the desk does, not what a launch might.

## What this checklist does not do

It decides nothing. The signers (A4), the reviewer (A2), the launch and the pool are people's decisions, recorded when made. It does not launch the token or choose where. It does not cover the position product's own deployment (rows 1–6 of [the deployment plan](DEPLOYMENT.md)), which waits on its own gate decision. It does not hold, make or ask for a key.
